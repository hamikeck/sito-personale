# Blog completo: gallery, pagina articolo, cover e correlati

Data: 24 luglio 2026 · Stato: **implementato e verificato** (build, lint, controllo visivo su gallery, articolo con cover, articolo con fallback, homepage)

## Obiettivo

Portare il blog dallo stato attuale (lista semplice + pagina articolo minimale) a un blog completo: gallery "in evidenza + griglia", pagina articolo con layout di lettura curato, immagine di copertina opzionale con fallback grafico, tempo di lettura calcolato, articoli correlati, componenti shadcn/ui (stile base-nova, API verificate su context7 prima dell'uso).

## Gestione contenuti (decisione confermata)

Si mantiene il sistema esistente, che è già il "database in memoria" richiesto:

- Un file **MDX** per articolo in `content/articoli/<slug>.mdx`; lo slug è il nome del file e definisce l'URL `/articoli/<slug>`.
- Metadati esportati in testa al file: `titolo`, `descrizione` (short text), `data` (ISO), `tag[]`, più i nuovi campi **`cover?`** (path immagine, opzionale) e `bozza?` (già esistente).
- Compilazione a build time: `getArticoli()` legge la cartella, `generateStaticParams` + `dynamicParams = false` generano le pagine statiche. Nessuna dipendenza nuova per i contenuti.
- **Immagini**: una cartella per articolo in `public/articoli/<slug>/` (es. `cover.jpg`, `foto-1.jpg`), referenziate nel Markdown con la sintassi standard `![alt](/articoli/<slug>/foto-1.jpg)`.
- **Tempo di lettura**: calcolato a build time contando le parole del file MDX (~200 parole/minuto), esposto insieme ai metadati. Non va scritto a mano.

Alternative scartate: file TypeScript con contenuto in stringa (scomodo da scrivere); Markdown puro + frontmatter YAML (richiede librerie aggiuntive per replicare ciò che `@next/mdx` fa già).

## Gallery `/articoli` — "in evidenza + griglia"

- **Card in evidenza** (articolo più recente): larghezza piena, su desktop cover a sinistra (~55%) e testo a destra, impilati su mobile. Etichetta "ULTIMO" in `font-mono` su sfondo `secondary` (ambra). Titolo `text-3xl`, descrizione, meta `font-mono` (data · tempo di lettura), badge tag.
- **Griglia**: gli altri articoli in `sm:grid-cols-2`, card verticali con cover 16:9 in alto (`border-b-2` a inchiostro), poi meta, titolo, descrizione.
- **Filtri tag**: mantenuti (stato client come oggi in `ElencoArticoli`), ristilizzati con Badge shadcn cliccabili.
- **Hover**: `hover:-translate-y-1` + `shadow-brut`, coerente con le card esistenti.

## Pagina articolo `/articoli/[slug]`

Dall'alto: link "← tutti gli articoli" → cover (o fallback) `rounded-2xl border-2 shadow-brut`, rapporto ~2:1 → `h1` `text-4xl/5xl font-extrabold` → riga meta (data · tempo di lettura · badge tag) → corpo in `max-w-2xl` con `prose` → `Separator` → sezione **"Continua a leggere"** con 2 card di articoli correlati (più tag in comune; a parità, i più recenti; esclusi i correnti/bozze).

Le immagini nel corpo Markdown vengono rese via `mdx-components` con `next/image` in cornice neobrutalista; l'alt text diventa didascalia sotto la foto.

## Fallback cover

Componente grafico generato dal sito quando `cover` è assente: sfondo **arancione (`primary`) o ambra (`secondary`)** scelto in modo deterministico dallo slug (hash semplice), titolo dell'articolo in tipografia gigante `font-extrabold`, bordo a inchiostro. Stesso linguaggio delle OG image già realizzate con `next/og`. Usato sia nelle card sia in testa alla pagina articolo.

## Accessibilità

Un solo `h1` per pagina; alt text obbligatorio nelle immagini Markdown; focus visibile sui filtri tag; contrasti garantiti dalla palette inchiostro-su-carta esistente.

| Immagini nel corpo | `mdx-components.tsx` | mapping `img` → `next/image` con didascalia |
| shadcn/ui | `components/ui/` | installazione `card`, `badge`, `separator` via CLI (API base-nova verificate su context7) |
| Esempio | `content/articoli/benvenuto.mdx` | aggiornato come articolo di riferimento |
